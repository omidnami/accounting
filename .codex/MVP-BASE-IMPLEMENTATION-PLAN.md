# برنامهٔ اجرایی MVP پایهٔ حسابداری

آخرین به‌روزرسانی: ۲۰۲۶-۱۱-۲۸
وضعیت: `P0-01` انجام شده؛ آمادهٔ شروع `P0-02`.
نقطهٔ شروع پیشنهادی: `P0-02`

## هدف

تثبیت نسخهٔ پایهٔ حسابداری پیش از توسعهٔ ماژول‌های صنفی و تخصصی؛ با حفظ یک codebase و دو حالت استقرار.

## دامنهٔ فعلی

### داخل دامنه

- زیرساخت حسابداری، Coding و تفصیلی
- ارز و ارز پایه
- نقش‌های طرف‌حساب
- مرکز هزینه و مرکز سود
- مانده‌های اولیه
- خزانه‌داری کامل
- اصلاح و ابطال اسناد
- ورود گروهی اطلاعات
- پیش‌فاکتور
- مدیریت انبار و اطلاعات مجموعه
- گزارش مالیات خرید و فروش
- موتور ماژول، مجوزها و منوهای پویا
- Backup و عملیات استقرار

### خارج از دامنه تا پایان MVP پایه

- Print Agent و بازطراحی آن
- صندوق مستقل تحت ویندوز/لینوکس/مک
- مدیریت پرینتر روی سرور
- نمایش فاکتورهای شیفت در اپلیکیشن مستقل
- طراح قالب فاکتور و سربرگ‌ساز
- موتور فاکتور سفارشی
- Industry Packهای صنفی
- حقوق و دستمزد، دارایی ثابت، تولید، پیمانکاری و ارز پیشرفته

برای فاکتور و سربرگ فقط قرارداد extensibility رعایت می‌شود؛ UI، template engine و designer ساخته نمی‌شود.

# قواعد اجرای تسک‌به‌تسک

1. هر بار فقط یک تسک فعال باشد.
2. پیش از شروع تسک، وابستگی‌های آن باید ✅ شده باشند.
3. تغییر schema یا migration فقط پس از تأیید ERD و ماتریس ثبت انجام شود.
4. هر تسک باید تست، مستندات و کامیت مستقل داشته باشد.
5. پس از اتمام، وضعیت تسک در همین فایل به ✅ تغییر کند.
6. در جدول «گزارش پیشرفت»، تاریخ، نتیجه، شواهد تست و کامیت ثبت شود.
7. عملیات حساس مثل ورود گروهی، backfill و restore ابتدا اجرای آزمایشی داشته باشند.
8. Print Agent و طراحی فاکتور/سربرگ در این چرخه اصلاً لمس نمی‌شوند.
