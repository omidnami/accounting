# Phase 4A: خزانه و چرخه چک

وضعیت کلی: تکمیل شد

## قواعد

- هر دریافت/پرداخت نقدی یا بانکی به TreasuryAccount واقعی متصل است.
- حساب خزانه به حساب معین دفتر کل متصل است.
- چک دریافتی پس از ثبت، Pending است و تا وصول به بانک/صندوق منتقل نمی‌شود.
- چک پرداختی پس از صدور، Pending است و تا خرج‌شدن، حساب بانکی را کاهش نمی‌دهد.
- وصول/خرج چک سند جداگانه ایجاد می‌کند.
- برگشت چک سند معکوس می‌سازد و مطالبات/بدهی را بازمی‌گرداند.

## چک‌لیست

- [x] ساخت TreasuryAccount
- [x] اتصال Receipt/Payment به حساب خزانه
- [x] Seed صندوق و بانک
- [x] سرویس وصول چک دریافتی
- [x] سرویس خرج‌شدن چک پرداختی
- [x] سرویس برگشت چک
- [x] بازگرداندن وضعیت فاکتور پس از برگشت چک
- [x] تست‌های lifecycle خزانه
- [x] migration، seeder و CI

## گزارش نهایی

- `treasury_accounts` به حساب معین دفتر کل متصل است.
- دریافت و پرداخت نقدی/بانکی به حساب خزانه واقعی متصل می‌شوند.
- صندوق و بانک اصلی seed شدند.
- صدور چک، وصول/خرج و برگشت سه مرحله مستقل دارند.
- چک تا تسویه Pending باقی می‌ماند.
- وصول/خرج و برگشت چک سند حسابداری مستقل ایجاد می‌کنند.
- برگشت چک، سند خزانه را Bounced و وضعیت فاکتور را دوباره باز می‌کند.
- CI نهایی: ۱۰۲ تست موفق، ۳۶۷ assertion، PHPStan صفر خطا و Pint موفق.
