# Phase 12A: Dashboard تحلیلی واقعی

وضعیت: پیاده‌سازی و تست محلی تکمیل شد؛ commit توسط کاربر انجام می‌شود.

## هدف

جایگزینی داده‌های placeholder Dashboard با snapshot واقعی از اسناد Posted،
فاکتورها، مانده‌ها، چک‌ها و موجودی، همراه با کنترل دسترسی بر اساس نقش.

## نماهای نقش‌محور

- `manager` و `accountant`: نقدینگی صندوق/بانک، مطالبات، بدهی‌ها، فروش و خرید
  امروز، فاکتورهای باز، چک‌های نزدیک سررسید، سود دوره، موجودی کم و فعالیت‌ها.
- `cashier`: فروش خالص امروز، فاکتورهای باز، پیش‌نویس‌ها و آخرین فروش‌ها؛ بدون
  داده بانک، خرید یا بدهی تأمین‌کننده.
- `warehouse`: فقط هشدار نقطه سفارش و مقدار موجودی؛ بدون مبالغ مالی.
- `viewer`: نمای محدود بدون داده تحلیلی مالی.
- نصب ناقص: پیام راه‌اندازی به‌جای خطا.

## پیاده‌سازی

- `DashboardController`.
- `DashboardService`.
- `CustomerReceivableService::storeOutstanding`.
- `SupplierPayableService::storeOutstanding`.
- نمودار فروش/خرید خالص هفت روز اخیر.
- فعالیت‌های اخیر فاکتور، دریافت و پرداخت.
- هشدار موجودی بر اساس نقطه سفارش در سطح شعبه.
- مرز تاریخ گزارش‌ها با `whereDate` برای SQLite/MySQL یکسان شد.

## تست

- نصب ناقص و کاربر بدون Store.
- Dashboard مالی مدیر و حسابدار با فروش، دریافت، مانده و کمبود موجودی.
- عدم افشای داده مالی به Cashier.
- نمای محدود Warehouse.
- عدم نمایش تحلیلی برای Viewer.

## نتیجه محلی

- Pest: 226 تست موفق، 1659 assertion
- PHPStan: صفر خطا
- Pint، Vue lint و type-check: موفق
- Frontend build: موفق
- migration جدیدی لازم نبود

## محدودیت‌های باقی‌مانده

- Dashboard بدون cache است و برای داده‌های بزرگ نیاز به snapshot یا cache
  دوره‌ای دارد.
- نمودار فعلی هفت‌روزه است؛ نمودار ماهانه شمسی در فاز بعد اضافه می‌شود.
- بررسی دستی مرورگر و MySQL CI روی commit جدید باقی مانده است.
- فایل `Dashboard.vue` قدیمی دیگر route ندارد؛ حذف آن در پاک‌سازی بعدی انجام
  می‌شود.
